# Brief to Scene

Use this reference to turn words into a visual argument before discussing style.

## 1. Meaning Map

Write six short lines:

1. **Claim** — what the audience should understand.
2. **Starting state** — what exists before the change.
3. **Change engine** — the action, pressure, decision, or mechanism that creates change.
4. **Ending state** — the visible result.
5. **Concrete inventory** — real objects, places, people, materials, and signals implied by the input.
6. **Forbidden readings** — plausible but wrong meanings the imagery must avoid.

Do not start with a visual metaphor. First establish the literal logic. A metaphor is accepted only if it preserves the same starting state, change engine, and ending state.

## 2. Choose the Architecture

### Impact beat

Use when one visual contradiction or transformation can prove the claim. Target 4–6 seconds and one final composition.

Shape:

- establish the visual premise;
- introduce one disruptive action;
- reorganize the pieces;
- lock into an image that resolves the idea.

### Evidence chain

Use when the audience must follow a journey, mechanism, or causal explanation. Target three to five states and 8–15 seconds.

Shape:

- identify the source;
- show the first irreversible change;
- show transfer or accumulation;
- show the destination or consequence;
- optionally reveal a final comparison.

Each state must contribute information unavailable in the previous state. If two adjacent states communicate the same thing, merge them.

## 3. Build the Visual Proof

Describe the proof in three sentences:

- **First glance:** what the viewer recognizes immediately.
- **Tracked change:** which object or feature the viewer follows and how it changes.
- **Concluding evidence:** what final arrangement makes the claim undeniable.

Then create an object-role table:

| Object | Role | Enters | Interacts with | Settled state |
|---|---|---|---|---|
| concrete element | source/operator/carrier/obstacle/destination/evidence | beat | concrete partner | final location and form |

Remove an object if its role cannot be stated in one phrase. Combine objects that repeat the same function.

## 4. Control Complexity

Element count and narrative density are different. Use many elements only when they form readable clusters.

- One dominant subject or transformation per state.
- Two or three supporting clusters at most.
- Repeated small elements count as one cluster when they share behavior.
- Background texture cannot introduce a second story.
- Directional flow should be consistent across adjacent states unless reversal is the point.

For a premium fast sequence, increase the rate of meaningful changes, not the number of unrelated pieces.

## 5. Gate 1 — Production Plan

Before generating stills, present the official scene-workflow decision package:

- the one-sentence claim;
- architecture and duration;
- three to five state descriptions;
- tracked continuity token;
- final proving image;
- palette direction and aspect ratio;
- target duration and H3 sound policy;
- anything intentionally excluded.

Request approval when the user has not already approved that concept. This is Gate 1: approval is about production logic, not prompt wording. Do not generate or hand off a still prompt until Gate 1 is locked, unless the user explicitly supplied an already-approved production plan.

For a process or narrative journey, translate the approved states into `F0` through `Fn`, then plan one 5-second segment for every adjacent pair. The full duration is normally `(frame count - 1) × 5 seconds`. Do not compress several major causal stages into one segment merely to reduce the frame count.
